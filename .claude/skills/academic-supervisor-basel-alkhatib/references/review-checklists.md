# قوائم تدقيق المشرف حسب نوع المخرج

استخدم القائمة المناسبة بنداً بنداً. كل بند غير مستوفٍ يُذكر في المحضر مع درجته (جوهري/مهم/ثانوي).

## أ. الدراسة المرجعية (Literature Review)
**جوهري**
- [ ] تغطي المراجع المحاور الأساسية للرسالة: تحليل سلوك المتعلم، CF، CBF، الأنظمة الهجينة، التوصية المدركة للسياق، النماذج التسلسلية/العميقة، التقييم.
- [ ] لكل مرجع: الفكرة، البيانات المستخدمة، الخوارزمية، مقاييس التقييم، النتائج الرقمية، القيود — **لا ملخص إنشائي**.
- [ ] جدول مقارنة موحّد (المرجع/السنة/الوعاء/البيانات/الطريقة/المقاييس/أفضل نتيجة/القيود/علاقته بالرسالة).
- [ ] تحليل نقدي: ما الذي تتفق عليه المراجع؟ أين تتعارض؟ ما الذي لم يُدرَس؟
- [ ] **الفجوة البحثية** مستنتَجة صراحةً من الجدول، وتقود مباشرة إلى فرضيات الرسالة.
- [ ] كل مرجع في المتن له ملف في `references/` وتم التحقق من مصداقيته (DOI/الناشر/التحكيم) أو وُضع عليه تنبيه صريح.
- [ ] لا استشهاد بمصدر غير موجود أو غير قابل للتحقق.
**مهم**
- [ ] ترتيب منطقي (موضوعي أو زمني) لا عشوائي.
- [ ] الحداثة: نسبة معتبرة من المراجع خلال آخر 5 سنوات مع تبرير القديمة (أساسية/كلاسيكية).
- [ ] تنسيق استشهاد موحد (IEEE رقمي) وقائمة مراجع كاملة البيانات.
**ثانوي**
- [ ] المصطلحات الإنكليزية بين قوسين عند أول ذكر؛ لغة عربية أكاديمية سليمة.

## ب. الفرضيات والخوارزميات
**جوهري**
- [ ] كل فرضية: قابلة للاختبار، محددة بمتغيرات ومقياس وعتبة نجاح، ومرتبطة بفجوة بحثية.
- [ ] الخوارزميات المقترحة مبررة بالمراجع ومتوافقة مع قيود البيئة (`thesis-context.md`).
- [ ] خطوط أساس (baselines) مناسبة ومعروفة (Popularity, ItemKNN, UserKNN, MF/ALS, CBF...).
- [ ] بروتوكول تقييم صحيح: تقسيم زمني أو leave-last-out، لا تسرّب، مقاييس Top-N (Precision@K, Recall@K, NDCG@K, MRR, HitRate, Coverage).
- [ ] تعريف واضح لـ"سلوك المستخدم" وكيف يُحوَّل إلى إشارات (implicit feedback) وأوزان.
**مهم**
- [ ] جدول مصطلحات مع تعريف + مثال بسيط + أين يُستخدم في الرسالة.
- [ ] شرح كل خوارزمية بمثال عددي صغير قابل للتتبع يدوياً.
- [ ] مناقشة التعقيد الحسابي وقابلية التوسع.

## ج. اختيار عينة البيانات
**جوهري**
- [ ] مقارنة ≥ 3 مجموعات بيانات وفق معايير مكتوبة (الترخيص، الموثوقية/المصدر، وجود سجلات سلوك خام، الحجم، الحداثة، التوافق مع الفرضيات، قابلية التحميل فعلاً هنا).
- [ ] المجموعة المختارة تحتوي سلوكاً فعلياً (نقرات/مشاهدات/زمن/تسلسل) لا تقييمات صريحة فقط.
- [ ] تم تحميلها والتحقق منها فعلياً (عدد السجلات/المستخدمين/العناصر) وتوثيق ذلك.
- [ ] تحليل استكشافي (EDA) أولي: التوزيعات، التناثر (sparsity)، الذيل الطويل.
**مهم**
- [ ] خطة معالجة مسبقة واضحة (تنظيف، تصفية المستخدمين/العناصر النادرة، بناء الجلسات).

## د. التحليل والتصميم
**جوهري**
- [ ] متطلبات وظيفية وغير وظيفية مرقّمة، وحالات استخدام للأدوار (متعلم، مدرّس/مشرف، إداري).
- [ ] معمارية مكوّنات بسيطة ومبررة؛ كل مكوّن له مسؤولية واحدة.
- [ ] مخططات: حالات الاستخدام، المكوّنات/المعمارية، خط معالجة البيانات، تسلسل التوصية، نموذج البيانات — مرقّمة ومشروحة.
- [ ] مصفوفة تتبّع: متطلب ← مكوّن ← ملف كود ← اختبار.
**مهم**
- [ ] اختيار stack مبرر بالقيود البيئية.
- [ ] خطة تطوير بمراحل ومعايير قبول.

## هـ. الكود والنتائج التجريبية
**جوهري**
- [ ] يعمل من الصفر بأمر واحد موثّق؛ البذور العشوائية مثبّتة.
- [ ] كل رقم في جداول النتائج يولَّد من كود موجود في `src/` ومحفوظ في ملف نتائج.
- [ ] مقارنة عادلة مع خطوط الأساس على نفس التقسيم ونفس المقاييس.
- [ ] تحليل حساسية أو ablation للمكوّن السلوكي (ماذا يحدث بدون إشارات السلوك؟).
- [ ] اختبارات وحدة للمقاييس وخط المعالجة.
**مهم**
- [ ] مناقشة صادقة للنتائج السلبية والقيود.
- [ ] واجهة مستخدم تعرض التوصيات وتفسيرها، مع لقطات شاشة.

## و. الأطروحة النهائية
راجع `thesis-standards.md`. جوهري: البنية الكاملة، تماسك "مشكلة ← فجوة ← فرضيات ← منهجية ← نتائج ← مناقشة ← خاتمة"، كل جدول/شكل مرقّم ومُشار إليه في المتن، الخاتمة لا تدّعي أكثر من النتائج، قائمة مراجع IEEE كاملة.

## ز. العرض التقديمي
- [ ] 15–20 شريحة لمدة 15–20 دقيقة؛ تسلسل: العنوان ← المشكلة ← الهدف ← الفجوة ← المنهجية ← البيانات ← النظام ← النتائج ← المناقشة ← القيود ← الخاتمة ← شكر.
- [ ] رسالة واحدة لكل شريحة، أشكال بدل النص حيث أمكن، خط كبير مقروء، لا فقرات.
- [ ] شريحة احتياطية للأسئلة المتوقعة.
